# Adding a read-only game adapter

1. Implement `GameAdapter` from `src/main/services/game/types.ts`. `detect()` must be cheap, bounded and side-effect free. Emit normalized `game_event` objects with a unique ID, game ID, timestamp, priority, type and factual payload. Prefer an officially documented read-only integration when available.
2. Keep polling and resources inside the adapter. `start()` and `stop()` must be idempotent. Cancel timers on stop and check a session generation after asynchronous operations so an old request cannot emit into a new session. `adapters/read-only-game.ts` provides this pattern for polling adapters. Treat missing data as unknown; never invent kills, results or other events after a sample gap.
3. Register the adapter in `game-event-bus.ts`. Exclude its process/name from generic commentary in `game-commentary.ts` to avoid duplicate reactions. Integrate its process with the existing `system-observer.ts` Gaming Mode lifecycle, including startup with the game already open and shutdown with another game still active.
4. Reuse event types where they fit. Add only the required new types and templates. Route speech through `ReactionEngine` so silence, priority and frequency apply. Supply fallbacks for all ten text languages; an English/Spanish template is not automatically translated unless it exists in the shared line catalog. Guard pending narration against silence, frequency, language and session changes.
5. Read only: no input automation, game-memory reads, injection or process manipulation. Keep credentials out of events, prompts, fixtures and logs. Bound requests and file reads. If using unofficial endpoints, document that clearly rather than claiming approval. For pixel observations, capture only the foreground game window, verify focus again after capture, and keep pixels local.
6. Add meaningful offline tests for actual state transitions, missing/invalid samples, duplicate suppression, restart/stop behavior, language fallbacks and settings. Use anonymized fixtures. Document prerequisites, event coverage, unsupported cases and the platforms actually tested in the README.

Valorant is an example of unofficial read-only HTTP plus local HUD observation. Its fallback templates live in `valorant-templates.ts`; `factual-commentator.ts` optionally rewrites observed facts through the configured LLM with a bounded timeout and a language check. These checks are heuristic, so deterministic fallbacks remain necessary.

Run `npm run test:game-reactions`, `npm run typecheck` and `npm run build`. Tests use mocked HTTP/capture and saved HUD crops; they do not replace a live game test.
